# 提示词正文（从这里开始复制）

## 一、你的角色与目标

你是一名资深 Web 3D 前端工程师，同时具备初中物理教学理解力。你的任务是**从零实现一个初中物理 3D 可视化演示网站**，让学生通过拖拽和调参，直观看到物理规律如何起作用。

这个产品不是炫技的 3D 玩具，而是一个**能用在中考复习上的教具**：每个实验都要物理正确、参数可调、现象可观察、结论可验证。物理算错比画面难看严重得多。

## 二、技术底线（不可违反）

1. **必须使用 three.js 实现 3D 渲染**。版本基线 three r160+，使用 ES Module。
2. **不加载任何外部模型、HDR、字体文件**。所有几何体用 three 内置几何体程序化生成（`BoxGeometry`、`SphereGeometry`、`CylinderGeometry`、`LatheGeometry`、`TubeGeometry`、`ExtrudeGeometry` 等）。理由：首屏体积、离线可用、无版权风险。
3. **不得依赖 CDN**，所有资源本地打包。
4. 中文标注用 `CSS2DRenderer` 输出 DOM 标签，**禁止用 `TextGeometry`**（中文字体 json 数 MB，且无法换行、无法点击）。
5. 单个实验的实验逻辑必须**独立成模块**，新增实验不应修改任何已有实验的代码。
6. 所有物理量必须由公式计算得出，**禁止把结果硬编码成几组假数据播放动画**。调整参数后，数值与画面必须由同一套物理公式驱动。

## 三、视觉风格

左右分栏固定布局：

- **左侧：UI 控制面板**，宽 320–360px，深色系，可折叠。
- **右侧：3D 物理实验实时渲染区**，占据剩余全部空间。

整体基调：深色科技风，浅色文字，高对比度，克制且专业，像一块教学仪器面板而不是游戏界面。深色底的理由很实际：光路、电场线、波形在深底上对比度最高。

**色值必须与 UI 规范同源**，3D 侧禁止自己另定一套：

| 用途 | 值 |
|---|---|
| 3D 场景背景 / 雾色 | `#0B1120` |
| 力学识别色 | `#F59E0B` |
| 电学识别色 | `#FACC15` |
| 光学识别色 | `#A78BFA` |
| 声学识别色 | `#34D399` |
| 热学识别色 | `#FB7185` |
| 主色（选中、焦点） | `#3B82F6` |

- 场景背景用 `#0B1120` 起手的**轻微径向渐变**（中心略亮、边缘压暗）配合 `scene.fog`（雾色同为 `#0B1120`，`FogExp2` 或 `Fog(近, 远)`），让远处物体自然退到背景里，不出现"浮在黑板上"的悬浮感。
- 每个实验的力矢量、光路、波形、选中高亮一律用所属模块的识别色，学生任何时候都知道自己在看哪个学科。
- 配柔和的接触阴影（`ShadowMaterial`），让模型有"站在地上"的真实感。
- 所有物理量标注（力矢量、光路、电流方向、波形刻度）必须有单位，且单位与数值一起实时更新。
- 数字用等宽字体（UI 侧 `--font-mono`），避免拖动滑杆时数字宽度跳动；3D 内的 CSS2D 标签同样用等宽字体显示数值。
- 禁止花哨的发光、粒子特效堆砌；任何视觉元素必须服务于"看懂物理"。

## 四、交互规范

1. **鼠标拖拽旋转查看模型**：左键拖拽旋转，滚轮缩放，右键或右键拖拽平移（如启用）。必须有阻尼感，不能一松手就停死。限制最小/最大缩放距离，防止把视角转丢或钻到地面以下。
2. **左侧面板点击切换实验场景**：按力学/电学/光学/声学/热学五大模块分组，可折叠。切换时相机过渡到该实验的预设机位，不做硬切。
3. **参数实时调节**：每个实验提供 2–6 个滑杆（如质量、摩擦系数、电压、电阻、焦距、频率），拖动时右侧画面与数值**实时同步**，不允许有明显延迟或需要松手才生效。
4. 提供一个「重置」按钮，恢复该实验的默认参数与默认视角。
5. 参数滑杆旁必须显示当前值 + 单位；并在旁边给出一个**由物理公式算出的结果量**（如加速度、电流、像距、波长），让学生看到"改了这个，那个变了"。
6. **状态词与数值互斥**：公式存在分段条件时（如 A1 的 μ≥tanθ 小车静止），读数区显示状态词（「静止」）并隐藏数值，**绝不显示负值或无效值**。这类状态词与数值共用一个显示位，二选一。
7. 关键物理现象要有明确的视觉反馈：力矢量箭头随参数伸缩、电流粒子随电流变速、光线随折射率偏折、波形随频率变密。

## 五、内容范围（中考考纲核心实验与物理模型）

必须覆盖以下五大模块共 **25 个 P0 场景**（力学 7、光学 5、声学 3、电学 7、热学 3），逐条清单见【附录 A：实验清单】。每个实验都要做到：模型正确、参数可调、现象可见、结论与教材一致。

**章节号按人教版新教材**：八上（2024 秋）、八下（2025 春）、九年级全一册（2025 秋）。注意新教材已重排——八上第一章是「机械运动」不是「声现象」，九年级合并为全一册并新增各章「跨学科实践」节。**不要沿用旧版章节编号。**

**参数范围不许自己猜**：附录 A 与 `docs/附录A-实验清单.json` 给了每个参数的四元组（min/max/step/default/unit）和闭式解公式，照抄即可。25 个实验全部是解析式，**不需要引入物理引擎**。

不得用"几个通用立方体换个标题"的方式凑数量——每个实验的模型形态要能反映该实验的物理结构。

## 六、每个实验的统一实现规范

所有实验必须实现同一个接口，由框架统一调度：

```ts
// core/types.ts —— 全项目唯一的实验契约，不得出现第二套
export interface NumberParam {
  type?: 'number';                      // 省略即 number
  key: string;                          // 'mass'
  label: string;                        // '质量 m'
  unit?: string;                        // 'kg'
  min: number; max: number; step: number; default: number;
}

export interface EnumParam {
  type: 'enum';                         // 离散档位，不做滑杆
  key: string;                          // 'surface'
  label: string;                        // '表面材料'
  unit?: string;
  options: { label: string; value: number | string }[];
  default: number | string;
}

export type ParamSchema = NumberParam | EnumParam;

export interface ExperimentContext {
  scene: THREE.Scene;
  onParam(key: string, value: number | string): void;    // 参数 → 模型更新（枚举值原样传入，实验自己 switch）
  step(dt: number): void;                                // 每帧调用，dt 已乘速度倍率
  emitReadout(v: Record<string, number | string>): void; // 推读数给 UI（只显示，不参与控制流）；键即读数卡标题字段，对应 JSON 的 result / secondaryResult
}

export interface Experiment {
  id: string;                           // 'mechanics.incline'
  name: string;                         // 中文标题
  module: 'mechanics' | 'electricity' | 'optics' | 'acoustics' | 'thermal';
  chapter: string;                      // 教材章节，如 '人教版八下 · 11.2'
  params: ParamSchema[];                // 左侧面板据此自动生成滑杆
  duration: number;                     // 时间演化总时长（秒）；0 = 无时间演化，播放条与时间条置灰。
                                        // 时长随参数变化的场景，用 getter 实现（见第七节「时间拖动条」）。
  speedOptions?: number[];              // 统一档位 [0.5, 1, 2, 4, 8]，全实验复用同一套工具条
  defaultSpeed?: number;                // 默认 1；热学 F1/F2 声明 8；A2 声明 0.5（全程不到 1 秒）
  cameraPreset: { position: Vector3; target: Vector3 };
  build(ctx: ExperimentContext): void;  // 首次进入才调用（懒加载）
  seek(t: number): void;                // 把状态设到第 t 秒并重绘；必须确定性、可反复调用
  reset(): void;                        // 参数回默认 + 清仿真内部状态（摆角、相位、粒子进度）
  dispose(): void;                      // 释放资源，切出场景时调用
}
```

硬性要求：

- **每个实验必须提供自己的 `cameraPreset`，不要指望自动取景**。实测过：动态场景（活塞、摆球、轨迹线）在 `build()` 那一刻还没被参数和首帧 `step` 摆到位，此时算 `Box3` 会量到空壳，自动适配会算出过远、过近甚至 NaN 的机位，A6 曾因此渲染出 0 三角形。逐场景手写机位是可靠解——新增实验时补一条，代价远小于跟自动算法搏斗。
- **进入场景时不要出现「空画面」**：温度曲线、轨迹线这类随时间长出来的元素，`build()` 里要先画好坐标轴和第一个数据点，否则首帧是一个空黑框，看起来像坏了。

- **参数声明式配置**：左侧面板根据 `params` 自动生成控件——数值参数（`NumberParam`）生成滑杆，枚举参数（`EnumParam`）生成分段按钮或下拉（规则见附录 B），**不得为每个实验手写 UI**。当前清单共 79 个数值滑杆 + 35 个枚举控件（**以 JSON 最新版为准，文中数字不追改**），全部要自动渲染出来。
- **懒加载**：实验的 `build()` 只在首次进入时调用，不得在首屏构建全部实验。
- **数据单一来源**：UI 上显示的数字和 3D 画面读同一份 state，不得出现两套数据各算各的。
- **解析型与动态型区分**：受力分解、透镜成像、电阻分流这类参数一变就能直接算出的，参数变化时同步重算；单摆、弹簧、粒子运动这类需要演化的，用**固定步长积分**（1/120s 累加器），保证不同帧率下物理结果一致。
- 新增一个实验，只允许新增一个文件 + 在注册表里加一行。如果为了加实验改动到框架代码，说明架构错了。

主循环骨架（顺序不能乱）：

```ts
const FIXED = 1 / 120;
let acc = 0;
const changed = new Set<string>();

renderer.setAnimationLoop(() => {
  const dt = Math.min(clock.getDelta(), 1 / 30);   // 切标签页回来防跳变
  if (changed.size) {                              // 每帧最多应用一次
    for (const k of changed) ctx.onParam(k, params[k]);
    changed.clear();
  }
  if (playback.playing) {
    acc += dt * playback.speed;                    // 速度倍率只作用于仿真时间
    while (acc >= FIXED) { ctx.step(FIXED); acc -= FIXED; }
  }
  controls.update();
  renderer.render(scene, camera);
  css2dRenderer.render(scene, camera);
});
// 页面不可见时 renderer.setAnimationLoop(null) 停掉，回到可见再恢复
```

滑杆 `input` 只做 `params[key] = v; changed.add(key)`，**不做 debounce**（debounce 会拖出明显手感延迟），靠 rAF 合并成每帧一次。

### 播放控制（暂停 / 速度倍率）

视区左下角的播放工具条要有实际作用，不能是装饰。统一由框架层持有 `playback = { playing: boolean; speed: number }`，**速度档位由实验自己声明，不是全局固定三档**（字段定义见第六节 `Experiment` 接口：`speedOptions` / `defaultSpeed`）。

```ts
const dt = Math.min(clock.getDelta(), 1 / 30);
if (playback.playing) {
  acc += dt * playback.speed;          // 速度倍率只作用于仿真时间，不改变渲染帧率
  while (acc >= FIXED) { ctx.step(FIXED); acc -= FIXED; }
}
// 暂停时 controls、render 照常跑，学生仍能旋转观察冻结的瞬间
```

硬性要求：

- **暂停不等于停渲染**。暂停时相机、光照、滑杆调参仍要正常响应，只是仿真时间不再推进。
- **速度倍率作用于仿真步进，不改帧率**。2× 是物理演化快两倍，不是渲染两次。
- 暂停时 `step` 不调用，但 `ctx.onParam` 照常执行——暂停状态下拖动焦距、电压，画面必须立刻更新。
- 切换场景时 `playback.playing` 重置为 `true`，`speed` 重置为该实验的 `defaultSpeed`（不是沿用上一个场景的倍率——从热学 8× 切到单摆还保持 8× 会让单摆快得看不清）。
- **置灰判据全站统一为 `duration === 0`**，不要按「解析型 / 动态型」去判。判据写在实验自己身上，框架不猜：`duration > 0` 的实验（哪怕它是解析式，如 F1 熔化曲线、F2 沸腾）播放条和时间条都可用；`duration === 0` 的实验两者一起置灰并标注「本实验无时间演化」。
- **热学场景默认 8×**，原因见附录 A.3：F1 平台段在 1× 下要 7~18 分钟，学生等不到平台结束，验收也没法测。
- 重置时除参数外，还要调 `reset()` 把仿真内部状态归位，否则单摆会从上次的摆角接着摆、温度曲线会接着上次的点画。

### 时间拖动条（每个实验都有）

视区底部居中放一条时间拖动条，学生可以把演示拖到任意时刻反复观察。这是**接口级要求**，不是外壳装饰：

```ts
// 实验侧：把状态设到第 t 秒并重绘。必须确定性——同样的 t 每次调用都要得到同一幅画面。
seek(t: number): void {
  if (this.duration === 0) return;
  const target = clamp(t, 0, this.duration);
  if (this.analytic) {          // 解析型：直接算该时刻的状态，不要重放
    this.t = target; this.applyStateAt(target);
  } else {                      // 积分型：清状态，用固定步长从头重放到 target
    this.resetSim();
    for (let s = 0; s < target; s += FIXED) this.step(FIXED);
  }
  this.redraw();
}
```

硬性要求：

- **`duration` 要能随参数变，用 getter 实现**。有六个场景的演示时长由参数决定（F1 由记录时长参数、D5 由通电时间参数、A1/A2/F2/F3 由 θ / μ / 水量 / 转速算出），写成常量会在改参数后立刻失真。做法：字段声明为 `number`，实现写成 `get duration() { return 计算式; }`，**外壳在「进入场景」和「参数变化后」各读一次**（或每帧重读，成本只是一次属性读取）。这样接口类型始终是 `number`，不需要 `number | ((params)=>number)` 这种联合类型，也不靠实验在 `onParam` 里回写字段——回写会漏，getter 不会。
- **getter 里不许有死代码**：声称随参数变，就要在整个参数定义域上真的变。A3 曾写成 `clamp(4/pull, 4, 12)`，而 `pull ∈ [0.05, 0.3]` 时 `4/pull` 恒大于 12，全被夹到上限，参数怎么调时长都是 12——这句依赖是假的。写完必须取参数域的两个端点代进去算一遍，两端相等就说明这个依赖没生效。
- **JSON 里的 `duration` 只是默认参数下的快照，不是权威值**。凡是时长随参数变的场景，JSON 里标 `durationIsSnapshot: true` 并给 `snapshotTolerance`（取 0.1），验收探针断言 `|exp.duration − snapshot| < max(tolerance × |snapshot|, 0.1s)`；一脱节就报错，不靠人记得去核对。**必须带这个绝对下限**——快照为 0 的场景（如 A7 默认平衡）相对容差会退化成 0，任何非零实现值都会误报。
- **注意命名冲突**：F1 自己有一个名为 `duration` 的参数，实验里读参数要用 `this.p.duration`，接口那个是 `this.duration`。两者同名，代码里必须分清楚，否则会自己递归调用自己。
- **无界过程和「没有过程」要分开，别用一个统一观察窗糊过去**。这两种情况性质不同，处理也不同：
  - **真正的无限运动**（A2 选理想光滑 μ=0，车永远匀速前进）→ `duration = Infinity`。时间条禁拖、读数显示 `t / ∞ s`，播放不会自动暂停但可以手动停。**不要给它一个假终点刻度**——20 秒窗口会在时间轴上长出一个「到头了」的刻度，而教学点恰恰是「永不停」，两者互相打脸。
  - **根本没有过程**（F3 转速调 0，曲轴压根不转）→ `duration = 0`，走置灰 +「本实验无时间演化」。这不是无限长的过程，是不存在的过程。
  - **「有没有过程」也可能由参数决定**（A1 斜面：μ ≥ tanθ 时小车压根不动，μ < tanθ 时正常下滑）。这类场景**必须用 getter 在参数分支里返回 0 或正常值**，不能因为「它有可能静止」就把整个场景写死 `duration = 0`——那样默认参数下车会滑、时间条却永远置灰。判据永远是「当前参数下有没有过程」，不是「这个实验有没有可能没有过程」。
  - **判别法**：问一句「这个结论依赖参数吗」。依赖，就只能写在 getter 或运行时判定里；场景级字段（JSON 里的常量、标记位）只配表达**从头到尾都成立**的事实。凡是给场景打一个「可能有零/可能无限」的标记字段，最后都会被人当常量误用——所以这类标记字段一律不留，只写说明文字。
  - 两种都**不要循环重播**，循环会让学生以为小车滑回起点了。
- **置灰文案必须分两类写，不能一句通吃**。`duration === 0` 有两种来源，短语不能混用：
  - **static**（B1~B5、C2、D1~D3 这类压根没有演化过程的实验）→「本实验无时间演化」。
  - **branch**（A1 静止分支、A7 平衡态、F3 转速 0 这类「当前参数下没有过程」）→ 必须给情境化文案，写清「当前为什么没过程、怎么改才有」，例如「当前平衡，杠杆静止（改动任一参数使力矩不等即转动）」。**不能用「本实验无时间演化」**——学生看到这句会以为这一类实验根本没有这一维，从此不去调参数，实验就废了。
  - 文案本身由 JSON 的 `zeroHint` 字段下发（只有 branch 场景有），外壳取用，**不要在代码里硬编码中文**。
- **`duration` 存的是时间轴秒数，不是墙钟秒**。它等于时间条 `t / duration` 里那个数，也是 `simTime` 的量纲。墙钟实际用时 = `duration ÷ defaultSpeed`。因此 A2 允许把 0.55 秒的物理滑行在仿真内部拉长成 3.4 的时间轴秒（慢放看细节），F1/F2 的时间轴就是记录时长本身（600 / 420），**8× 只是让墙钟变成 75 秒，不要折算进 `duration`**。`seek(t)` 收到的 `t` 也是时间轴秒，实验内直接解物理方程，不用再除倍速。
- **没有演化的场景不要编时长**。几何光学稳态成像、稳态电路、波形按参数即时渲染（B1~B5、C2、D1~D3 等）本来就没有时间过程，`duration = 0` 走置灰是对的。它们的 `step(dt)` 里那种持续装饰动画（电子流、光源拖动）不进时间轴，别为了让时间条可用硬塞一个 3 秒。
- **拖动即暂停**：按下时间条立刻暂停，松手后保持暂停（学生要停下来看这一帧），点播放从当前位置继续。
- **解析型不要重放**：F1/F2/B 系列/D4 这类能直接算的，`seek` 直接算该时刻状态；**积分型必须从头重放**（清空内部状态再按 1/120 步长跑到 t），不许「跨步跳跃」近似，否则摆角、粒子相位会漂。
- **时长要包得住物理**：`duration` 取该实验演化到「已经没有新现象」的时刻。A2 是 0.5s 级的短过程，`duration` 给 3~4 秒；F1 平台段按 8× 折算后的时间给。
- **回放一致性**：拖到同一时刻两次，画面和读数必须完全一致。检验方式——随机取 5 个时刻来回拖，同一个 t 两次的可视状态和读数差值必须为 0。
- 时间条本身是 DOM 控件（复用滑杆 token，轨道 3px、已播放段用主色 `--color-primary` 而非模块识别色），**不得进 3D 场景，draw call 零新增**。

## 七、各模块实现要点

### 渲染器与相机配置基线（先落地这一段，再写实验）

```ts
const renderer = new THREE.WebGLRenderer({
  antialias: true,
  powerPreference: 'high-performance',
  alpha: false,
});
renderer.setPixelRatio(Math.min(devicePixelRatio, 2)); // 移动端 1.5
renderer.outputColorSpace = THREE.SRGBColorSpace;
renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = 1.0;
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFShadowMap;   // r187 起 PCFSoftShadowMap 已被移除，见下
renderer.shadowMap.autoUpdate = false;   // 只在参数变化/切场景时置 needsUpdate
```

- **相机**：`PerspectiveCamera(45, aspect, 0.1, 200)`。切场景时用 `position.lerp` + `controls.target.lerp` 做 **600ms** 过渡到该实验的 `cameraPreset`，禁止硬切。
- **光照**：`HemisphereLight(0xffffff, 0x444466, 0.6)` + 一盏投影主 `DirectionalLight` + 一盏无阴影补光。主光 `shadow.mapSize = 2048`，`shadow.camera` 收紧到场景包围盒（±5），否则阴影糊且大量浪费。
- **阴影类型**：r187 已**移除** `PCFSoftShadowMap`——常量虽然还导出，但赋给 `shadowMap.type` 时 `WebGLShadowMap` 会打一行 `PCFSoftShadowMap has been removed. Using PCFShadowMap instead.` 然后静默降级。照旧模板写就会在控制台留下这条警告。直接用 `THREE.PCFShadowMap`，需要更软的边缘就在材质和光照上做，别再指望这个枚举。
- **环境反射**：用 `RoomEnvironment` + `PMREMGenerator` **程序生成** envMap，供金属、玻璃材质使用（棱镜、透镜、磁铁、镜面），不加载 .hdr 文件。
- **背景与雾**：背景取 `#0B1120` 径向渐变，`scene.fog` 雾色同为 `#0B1120`。渐变用 CSS 画在 canvas 后面的容器上（`renderer` 设 `alpha: true` 或 `clearColor` 透明），**不要用 3D 天空球**——多一个 draw call 且边缘会露馅。
- **接影平面**：`ShadowMaterial({ opacity: 0.25 })`，比实体地面省一半像素。
- **谁能 castShadow 要严格筛选**：只有结构性主体（斜面、物块、容器、透镜、磁铁这类学生会看位置关系的东西）才 `castShadow = true`；**描点、刻度、网格、辅助线、粒子、装饰件一律 `castShadow = false`**。原因：阴影 pass 里每个投影物各算一次 draw call——D4 的散点图有 41 个小球用了默认 `castShadow = true`，一帧阴影重建就多出 31 个 draw call（46 → 77）。关掉后阴影重建帧和稳态帧都留在红线内。
- **验收按稳态帧判定**：`shadowMap.autoUpdate = false` 时，参数变化或切场景之后的那一帧要跑一次阴影 pass，draw call 天然比稳态高一截。**红线（≤60）按「切换完成 500ms 后、且期间不改参数」的稳态帧判定**；含阴影重建的那一帧单列为峰值参考，不计入判定——但峰值也要通过上一条把投影物数量压下来，不能放任它飙到两三倍。
- **OrbitControls**：`enableDamping = true`、`dampingFactor = 0.08`、`minDistance 2`、`maxDistance 30`、`maxPolarAngle = Math.PI * 0.495`（防钻到地面下）、`enablePan = false`（教学演示不需要平移，避免视角迷路）；触摸 `touches.ONE = ROTATE`、`touches.TWO = DOLLY_ROTATE`。
- **粗线**：光路、力矢量、标注线一律用 `Line2` + `LineMaterial`。`LineBasicMaterial` 的 `linewidth` 在绝大多数平台恒为 1，画出来的光路细到看不见。光束加 `AdditiveBlending` + `depthWrite: false`。
- **中文标签**：`CSS2DRenderer` 输出 DOM，标签统一挂在 `labelRoot` 下，切场景时整体清空（`labelRoot.innerHTML = ''`），不要逐个 remove。标签数值用等宽字体，`pointer-events: none` 默认关闭（除非标签本身要可点击）。

### 视觉元素与模块识别色的对应

五科识别色不是只用在 UI 上，3D 里也要贯穿，否则切换模块时画面没有"换学科"的感觉：

| 元素 | 用色 |
|---|---|
| 力矢量箭头、斜面/物块高亮 | 力学 `#F59E0B` |
| 电流粒子、导线高亮、磁场箭头 | 电学 `#FACC15` |
| 光路、折射光束、透镜轮廓 | 光学 `#A78BFA` |
| 声波、波形曲线、音叉 | 声学 `#34D399` |
| 温度—时间曲线、热流箭头、火焰、热机活塞 | 热学 `#FB7185` |
| 选中/焦点/激活态 | 主色 `#3B82F6` |

注意：中性结构件（地面、支架、刻度尺、桌面）一律用低饱和中性灰（`#2A3648`–`#475467`），不要染模块色——否则满屏彩色，识别色就失去意义了。识别色只给"物理量本身"和"选中态"。

### 器材必须做成实物，不能是积木

**这一节是硬性要求，不是美术建议。** 每个实验的器材必须让人**不看标签也能叫出名字**：小车要有车身、四个轮子和车轴；电池要有圆柱外壳和正负极帽；灯泡要有玻璃泡、螺口和灯丝；电流表要有表盘、指针和接线柱；烧杯要有玻璃壁和刻度线；磁铁要涂成 N 红 S 蓝；透镜要有镜片和镜框；温度计要有玻璃管、液柱和刻度。用一堆纯色方块拼出来的东西，学生认不出，实验的教学价值就丢了一半。

实施方式：

- **建立共享器材工厂**（`props.js`）：`cart()` / `battery()` / `bulb()` / `resistor()` / `ammeter()` / `beaker()` / `magnetBar()` / `lens()` / `screen()` / `springScale()` / `tuningFork()` / `thermometer()` / `cylinderAssembly()` 等，全场景复用，不允许每个实验自己现拼。
- **材质统一成五族**：金属（钢/亮钢/铁/铜/铝/黄铜）、玻璃（烧杯/透镜/灯泡壳/玻璃管）、橡胶（轮胎/导线皮）、塑料（表壳/按钮）、木质（斜面/支架）。同族共用一份材质单例。
- **器材用材质本色，不用模块识别色**。识别色只给力矢量、光路、波形、电流粒子这些数据元素；器材若也用识别色，满屏橙黄紫绿，反而认不出是什么东西。教学功能色单列白名单：导线红黑、磁极 N 红 S 蓝、不同液体的区分色、火焰发光、水银柱。
- **构件预算**：每件器材合并后 ≤6 个材质组、≤4 个独立运动零件；单场景器材种类 ≤8；重复器材（钩码、导线）用 `InstancedMesh`。**同材质、同节拍的静态构件必须用 `mergeByMaterial` 合桶**，只有会独立运动的零件（车轮、指针、活塞、摆球）才单独留。
- 判断标准：**截图遮住文字标签，还能一眼叫出器材名**，算达标。

### 力学

- **斜面受力**：斜面用 `PlaneGeometry` 旋转成形，物块用 `BoxGeometry`。三支箭头按公式实时计算长度：重力 `G = mg`、支持力 `N = mg·cosθ`、摩擦力 `f = μmg·cosθ`。改变倾角 θ 时，支持力和摩擦力箭头同步变化，这是这个实验的核心看点。
- **单摆**：细圆柱作绳 + 球作摆球，按 `θ'' = -(g/L)·sinθ` 用 RK4 积分。可调摆长 L 与初始角度，必须能观察到"摆长影响周期、质量不影响周期"。
- **弹簧振子**：螺旋线用 `TubeGeometry`，参数变化时**只修改 position attribute，不重建几何**。振幅 A、频率驱动 `y = A·sin(ωt)`。
- **滑轮组**：`TorusGeometry` 作轮，绳用 `Line2` + 方块，按绳长约束计算物块位置。可调物重、动滑轮数量，显示拉力与省力关系。
- **浮力**：半透明水面 + 物块，按排水体积计算浸没深度，浮力箭头长度随之变化。可调液体密度与物体密度。
- **平抛/自由落体**：轨迹用 `BufferGeometry` 预分配 512 顶点池 + `setDrawRange` 逐点增长，不得重新分配内存。可调初速度与重力加速度。

### 电学

- **串联/并联电路**：导线用 `CatmullRomCurve3` + `TubeGeometry`，每种电路预置一套曲线，切换用显隐 + 透明度过渡。电流用 `InstancedMesh` 小球沿曲线运动，速度与电流 I 成正比。
- **伏安法测电阻**：可调电压与电阻，用 3D 表盘指针 + `rotation.z` 映射量程，指针随参数实时偏转。
- **欧姆定律 / 电功率**：实时显示电压、电流、电阻、功率四个量，满足 `I = U/R`、`P = UI`。
- **电磁铁 / 通电导线磁场**：同心 `TorusGeometry` 环 + 箭头表示磁场方向，可调电流方向与大小，箭头随之反向/变密。用箭头表示右手定则。
- **滑动变阻器**：可拖动滑片改变接入阻值，电路中电流表读数与灯泡亮度同步变化。

### 光学

- **材质前提（已按实测改口径）**：棱镜、透镜、水、烧杯**一律用 `MeshStandardMaterial` 的 `transparent: true` + `opacity`（玻璃 0.18~0.35）**，不要用 `MeshPhysicalMaterial` 的 `transmission`。原因：`transmission` 会额外开一层渲染 target，draw call 和显存都翻倍，而这套演示的透明体全是教学仪器，用 opacity 已经够读出「这是玻璃」。这条同时适用于移动端，不再做两套降级。
- **平面镜成像**：镜面用 `metalness: 1` + envMap，光线按反射公式逐段计算，像与物关于镜面对称。
- **光的折射 / 色散**：三棱镜用 `CylinderGeometry(r, r, h, 3)` 做三棱柱。折射方向按**斯涅尔定律**逐段计算，色散用 7 条不同颜色的 `Line2` 分角度射出。可调入射角与介质折射率。
- **凸透镜成像**：`LatheGeometry` 旋转双凸剖面做透镜，三条特殊光线 + 薄透镜公式 `1/f = 1/u + 1/v`。可调物距 u 与焦距 f，像的位置、大小、虚实实时更新；虚像用虚线 + 半透明表示。
- **小孔成像**：带孔遮光板 + 光屏，光线用锥体半透明网格表示，可调孔径与屏距，观察倒立像的大小变化。

### 声学

- **声波传播**：多层 `SphereGeometry` 缩放 + opacity 衰减模拟球面波。可调频率观察波长变化。
- **波形显示**：`Line` 实时更新 y 值，振幅/频率直接改函数参数，配合频率计数字。
- **音叉振动**：两个 `BoxGeometry` 振臂做位移振动，振幅与音量成正比。
- **声音三特性**：音调、响度、音色三组可调参数，波形与球面波同步变化。

### 热学

- **熔化凝固曲线**：`Line2` 温度—时间曲线 + 左侧烧杯/试管模型。晶体走分段函数（升温段 → 平台 → 升温段），平台时长 `t=m·L/P`，升温段 `t=m·c·ΔT/P`，**两段共用同一组 m、P 参数**。非晶体（石蜡）单独一条单调曲线，无平台，要有"逐渐变软"的中间态视觉。凝固是熔化的反向过程，曲线镜像、放热。
- **水的沸腾**：烧杯 + `InstancedMesh` 气泡 + 温度曲线。气压→沸点按经验式映射（见附录 A.3），**不要线性插值或硬编码记忆值**。沸腾前气泡上升变小、沸腾时上升变大到液面破裂；沸腾后温度恒定，但加热仍在进行（热流箭头继续）。水量只改到达沸腾的时间，不改沸点——这条必须能在画面上被验证。
- **比热容与热机**：左侧三个同质量同吸热的样品（水/煤油/砂石）温度条对比，右侧四冲程热机。热机由**曲轴角单参数解析驱动**（曲柄连杆公式 + 720° 循环，详见附录 A.3），不做关键帧。四个冲程的视觉要点：吸气进气门开、压缩缸内变红、做功缸内最亮活塞下压、排气排气门开。只有做功冲程对外做功，这一点要在曲轴转速上体现（做功冲程转速略升，其余靠惯性）。

## 八、性能预算（硬指标）

- 桌面 1080p ≥60fps，中端手机 ≥30fps。
- **单场景** `renderer.info.render.calls ≤ 60`（验收红线 100），`triangles < 200k`。
- 首屏 JS（含 three vendor）gzip ≤ 250KB；单个实验 chunk gzip ≤ 15KB。
- 连续切换全部实验 3 轮，标签页内存增幅 ≤ 10%，无 WebGL 泄漏告警。
- 关键优化手段（必须做到）：
  - `shadowMap.autoUpdate = false`，只在参数变化或切场景时置 `needsUpdate = true`。
  - 几何体与材质走全局共享池 + 引用计数，切换场景不销毁共享资源，避免重复编译 shader。
  - 静态几何用 `mergeGeometries` 合并，重复元素用 `InstancedMesh`。
  - 分段数克制：球 24–32、圆柱 16–24、曲线 64。够圆就停。
  - 像素比上限 2（移动端 1.5）。
  - 页面不可见时暂停渲染循环（`visibilitychange`）。
  - 默认不开后处理；辉光只在桌面端开且半分辨率。
- 切场景前必须 `dispose()` 几何体与全部材质贴图；页面卸载时 `renderer.dispose()` + `forceContextLoss()`；监听 `webglcontextlost` 给出提示。

资源释放要覆盖材质上的**每一个贴图槽位**，只 dispose 材质本身会漏掉贴图：

```ts
function disposeObject(root: THREE.Object3D) {
  root.traverse((o) => {
    const m = o as THREE.Mesh;
    if (!m.isMesh) return;
    if (!isShared(m.geometry)) m.geometry?.dispose();   // 共享池资源靠 refCount，不在此销毁
    const mats = Array.isArray(m.material) ? m.material : [m.material];
    for (const mat of mats) {
      for (const k in mat) {
        const v = (mat as any)[k];
        if (v && v.isTexture) v.dispose();
      }
      mat.dispose();
    }
  });
}
```

切换时序：遮罩淡入 150ms → 构建新场景、套用相机 preset → 淡出 150ms → 延迟 300ms 再 dispose 旧场景（避免淡出过程中黑屏）。

## 九、验收标准（必须逐条自查并给出检查结果）

1. **物理正确性**：逐个实验用 3 组参数手算结果，与画面显示数值比对，误差在显示精度内。
2. **共享资源不重建**：在资源池的 `getGeo` / `getMat` 上打调用计数，连续切换 5 个实验来回一遍，`create` 计数必须不变（只增 `refCount`）；同时记录 `renderer.info.programs.length`，切换前后不得增长（增长即 shader 被重新编译）。
3. **拖动无 debounce**：滑杆 `input` 里打点计数，同一帧内多次触发时 `ctx.onParam` 对同一个 key 只能执行一次。快速来回拖动 2 秒，`renderer.info.render.calls` 不得随拖动线性增长，帧率保持稳定。
4. **实验基准表**：每个实验记录 `renderer.info.render.calls`、`triangles`、单帧耗时，输出成验收表格，后续新增实验直接对比，防止越加越卡。
5. **新增实验零框架改动**：现场新增一个实验，验证只需加一个文件 + 注册表一行。
6. **懒加载**：首屏 `build()` 只对默认实验调用一次，其余实验首次点击时才构建。
7. **移动端可用**：手机宽度下左右分栏不塌陷（面板变抽屉），触摸单指旋转、双指缩放可用。
8. **播放控制正确**：暂停时相机与滑杆调参仍正常响应，仿真时间不推进；2× 速度下物理演化是 1× 的两倍，渲染帧率不变；**置灰判据是 `duration === 0`**（不是「解析型」），热学场景默认 8× 且档位为 1/2/4/8，切场景时倍率回到该场景的 `defaultSpeed` 而非沿用上一个场景。
9. **时间拖动条正确**：每个实验都能拖到任意时刻——随机取 5 个 t 来回拖，同一 t 两次的画面与读数差值必须为 0（拖到 t 再拖回 t，不能漂）；积分型实验（单摆、粒子、活塞）不得用跨步跳跃近似，必须清状态后按 1/120 重放；拖动时自动暂停、松手保持暂停；`duration === 0` 的实验时间条置灰且不报错；时间条不新增 draw call。
10. **色彩同源**：3D 场景背景与雾色取自 UI 的 `#0B1120`，力矢量/光路/波形/温度曲线使用所属模块识别色，中性结构件不染模块色。切换五个模块时画面识别色随之改变。
11. **重置彻底**：点重置后参数回到教材默认值，且仿真内部状态归位（单摆不接着上次摆角摆、粒子回到起点、温度曲线清空重绘）。
12. **状态词与数值互斥**：公式有分段条件时（如 A1 的 μ≥tanθ 静止），读数区显示状态词替代数值，「静止」时不显示加速度、不出现负值。分段条件必须用最大静摩擦判断，不能用 μN 直接比。
13. **热学三项专项校验**：F1 平台时长与升温段共用同一组 m、P 参数（改质量两段同步变），非晶体无平台；F2 气压→沸点按 Antoine 公式算，**70kPa 必须算出 89.99℃（±0.5℃）**，水量只改到达时间不改沸点；F3 曲轴转 720° 一个循环、只有做功冲程对外做功、气门开合按 720° 判断而活塞位置按 360° 判断；F3 的 `W有` 上限必须随 `Q总` 动态钳制，**任何拖法都调不出 η>100%**，`Q总=0` 时显示状态词而非 NaN。

## 十、禁止事项

1. 禁止用假数据/挂载动画代替真实物理计算。
2. 禁止在渲染循环里创建对象（`new THREE.Vector3()` 之类必须在循环外复用）。
3. 禁止整包引入 addons（如 `from 'three/addons'`），必须按路径按需引入（如 `'three/addons/controls/OrbitControls.js'`）。
4. 禁止在 `setAnimationLoop` 里做 DOM 查询或重排。
5. 禁止把 UI 状态塞进 three.js 的 Object3D（如把参数挂在 mesh.userData 上做数据源）。
6. 禁止为了好看加入与物理无关的特效。
7. 禁止实验之间共享可变全局状态（每个实验必须是封闭的）。
8. 禁止把 3D 场景背景、识别色硬编码成和 UI 无关的色值；必须从同一份 token 常量表读取。
9. 禁止把播放/暂停做成"停掉渲染循环"——暂停只停仿真时间，渲染和相机控制必须继续。

## 十一、交付物

1. 可运行的完整项目，`npm install && npm run dev` 即可打开。
2. `README.md`：目录说明、如何新增一个实验（含完整示例）、每模块实验清单。
3. 一个验收报告：物理正确性手算对照表 + 第 9 节十三条检查的实际结果。
4. 代码必须通过 TypeScript 严格模式与 ESLint，无 `any` 泛滥。

## A.2 粒子与流体的材质策略（这几处最容易做砸）

上面 25 个实验的物理计算**全是闭式解**，不需要刚体引擎、不需要物理库。真正需要特殊处理的是这九处「看起来像连续介质」的视觉表现：

| 场景 | 做法 | 关键约束 |
|---|---|---|
| **C1/C2 纵波（疏密波）** | `InstancedMesh` 一排小球，x 固定、y/x 位移按 `A·sin(ωt−kx)` 逐实例写矩阵。**不用粒子系统**——纵波要的是"密度疏密"，`Points` 无法表达粒子间距压缩 | 实例数 60~120 即可；每帧只写 `instanceMatrix`，禁止重建几何 |
| **D1/D3 电子流** | 沿 `CatmullRomCurve3` 的 `InstancedMesh` 小球，`curve.getPointAt(t)` 推进；速度 ∝ I，密度也 ∝ I（两者都要变，只变速度会看不出电流大小） | 小球 30~60 个；I=0 时停住且半透明；同一帧内 `getPointAt` 调用次数控制在实例数级别 |
| **D6 磁感线** | 预先参数化的曲线族（每条 `CatmullRomCurve3` 采样 64 点）+ `Line2`。**不要用箭头堆叠或粒子流**，磁感线是静态场，用粒子跑会误导"磁场在流动" | 疏密由间距参数控制，不用改几何；N/S 反向时整组曲线镜像 |
| **A4 液面 + U 形管** | 液面用 `CylinderGeometry` 的透明顶面 + 内部 `BoxGeometry` 体积块；U 形管液柱高度用两根可缩放圆柱 | 液柱高度用 `scale.y` 改，不重建几何；透明度 0.35~0.5 |
| **A5 浮力溢出** | 溢出的液体用 `InstancedMesh` 小球沿抛物线落进量筒，`BufferGeometry` 预分配 200 实例池循环复用 | 溢出量对应 V排，视觉上是"滴落"不是"喷泉"；全浸后必须停止新增，这条是物理正确性的视觉证据 |
| **C3 回声脉冲** | 两个 `SphereGeometry` 同心壳 + `AdditiveBlending`，半径随时间扩张；回波壳反向 | 壳层 3~4 层即可；`depthWrite: false`，否则会互相遮挡 |
| **F1 温度—时间曲线** | `Line2` + 预分配 512 顶点 `BufferGeometry`，用 `setDrawRange` 逐点增长；平台段靠采样密度自然显形，**不要平滑插值**，否则平台会被抹成斜坡 | 曲线数据点即仿真状态，`reset()` 必须清空顶点索引并归零 |
| **F2 沸腾气泡** | `InstancedMesh` 实例池（40~80 个），每个实例独立控制半径与上升速度；沸腾前气泡上升缩小、沸腾时上升放大 | 半径用矩阵缩放写，不重建几何；气泡数量随火力变，但实例池容量固定 |
| **F3 四冲程热机** | 曲轴角度驱动活塞 `position.y` 与连杆旋转，气门开合用两片薄盒 `rotation`；缸内颜色用 `emissive` 强度映射温度 | 全部由曲轴角一个参数解析驱动，**不做关键帧动画**，否则调速和暂停会脱节。活塞位移必须用曲柄连杆公式，见 A.3 节 |

通用规则：**凡是"连续量"（液面高度、波形、磁场密度），都用 scale 或 attribute 修改，禁止重建几何；凡是"离散量"（电子、水珠、粒子），都用 `InstancedMesh` 实例池。** 这条比任何单点优化都省事。

## A.3 几处必须明确的处理口径（不写清楚开发一定做错）

**A1 的静止态**：μ ≥ tanθ 时小车不会下滑，此时必须**切换为「静止」状态、加速度显示 0、速度条归零**，不能继续按 `a=g(sinθ−μcosθ)` 算出一个负值显示出来。θ=5°（tan5°≈0.087）而 μ 上限 0.30，所以「静摩擦」这一档会经常被学生调到，是高频路径。同理，从静止开始的判断要用最大静摩擦（略大于滑动摩擦），不是直接拿 μN 比。

**A6 的阻尼**：按线性阻尼处理，`ζ` 上限 0.3。严格解下阻尼会让周期略变长（`T≈T₀/√(1−ζ²)`，ζ=0.3 时约 4.6%），**初中范围内按「周期不变」呈现**，`T=2π√(L/g)` 直接用。验收时若被判「周期应随阻尼变化」，以本条为准。单摆、弹簧的积分用固定步长 1/120s，避免不同帧率下衰减速度不一致。

**F3 的曲轴驱动**（方向对，但必须写死公式）：用曲轴角 `φ` 一个参数解析驱动活塞与气门，这个思路正确——关键帧动画没法做调速和暂停。但活塞位移**不能用 `sinφ` 近似**，必须用曲柄连杆公式：

```ts
// r 曲柄半径，l 连杆长度，φ 曲轴转角（从活塞上止点起算）
const s = r * (1 - Math.cos(phi)) + (r * r / (2 * l)) * Math.sin(phi) ** 2;
piston.position.y = topY - s;
```

用纯 `sinφ` 会让活塞在上止点附近运动不对称，学生看着"卡顿"，而且压缩比失真。`r/l` 取 0.25~0.3（接近真实发动机）。

**四冲程与曲轴角的对应关系必须按这个表实现**，这是最容易做错的地方：

| 曲轴转角 | 冲程 | 活塞 | 进气门 | 排气门 |
|---|---|---|---|---|
| 0°~180° | 吸气 | 上止点 → 下止点 | **开** | 关 |
| 180°~360° | 压缩 | 下止点 → 上止点 | 关 | 关 |
| 360°~540° | 做功 | 上止点 → 下止点 | 关 | 关 |
| 540°~720° | 排气 | 下止点 → 上止点 | 关 | **开** |

要点：**曲轴转 2 圈（720°）完成一个工作循环，只有做功冲程对外做功**。活塞每 360° 回到原位，所以活塞位置是 `φ mod 360°` 的函数，而气门开合与"哪个冲程"必须用 `φ mod 720°` 判断——**这两个周期不同，混用一定会出现气门在错误冲程打开的 bug**。

**转速与曲轴角的关系**：`φ += 6 * rpm * dt`（rpm 转 °/s 是 `rpm * 360 / 60 = 6 * rpm`）。转速参数只改这个系数，**不要用 `dt` 之外的累计时间**，否则调速时会跳变。

**F2 的气压—沸点映射**：不能线性插值，也不要写记忆值。用 Antoine 方程闭式解（水，101.3kPa 基准）：

```ts
// p 单位 kPa，返回沸点 ℃
const mmHg = p * 7.50062;
const Tboil = 1730.63 / (8.07131 - Math.log10(mmHg)) - 233.426;
// 自检：101.3kPa → 99.99℃；70kPa → 89.99℃（真实 89.9℃）
```

**自检值 89.99℃ 是验收基准**，任何实现算出来必须落在这个数附近（±0.5℃）。不要用"70kPa 约 90℃"这类记忆值硬编码。

**F1 的平台长度**：平台时长由潜热决定，不是随便给的。`t_platform = m·L_fusion / P`（冰 `L=334 kJ/kg`，海波约 `L=250 kJ/kg`）。升温段 `t = m·c·ΔT / P`。**两段必须用同一套 `m`、`P` 参数算出来**，否则学生把质量调大一倍会发现平台变长但升温段没变，物理就错了。石蜡是非晶体，**没有平台**，实现上要单独走一条 `T = f(t)` 的单调曲线，不能用晶体那套分段逻辑加个"平台长度=0"糊弄——非晶体还有"变软"这个中间态。

> **潜热常数不进验收**：冰 334 kJ/kg 是通用值但初中教材不列，海波 250 kJ/kg 是近似值。这两个常数**只用于让平台时长成比例**，验收查的是「改质量两段同步变」，不查潜热绝对值。验收时若被判「潜热常数应为某值」，以本条为准。

**F1/F2 的时间倍速（必须做，否则实验看不到结果）**：按 150W、200g 冰算，升温段约 28s，而**平台段要 7.4 分钟**；质量调到 500g 平台要 18.6 分钟，直接超出时长上限。教材实验本来就是十几分钟的事，网页演示没人等。

- 播放工具条**全实验只做一套**，档位统一为 **0.5× / 1× / 2× / 4× / 8×**；热学 F1/F2 通过 `defaultSpeed` 声明 **默认 8× 且预选**。不要为热学另做一个工具条。
- 档位通过第六节 `Experiment` 接口的 `speedOptions` / `defaultSpeed` 声明，不是写死在工具条里；**切换场景时倍率要重置为该场景的 `defaultSpeed`**，不能沿用上一个场景（否则从热学 8× 切到单摆，单摆会快得看不清）。
- **不要为热学另做一套时间系统**。倍速就是第六节那个 `playback.speed`，作用于仿真时间，不改渲染帧率。
- 加热参数与器材必须对得上：F1 的实物是**酒精灯**，所以滑杆是「加热火力 1~5 档」而不是写一个瓦数——学生看到油灯、滑杆上标 260W，器材和参数就各说各话了。档位在代码里映射成等效吸热功率（60/100/150/200/300 W）参与公式，**时长计算与验收口径不变**，只是 label/unit/range 换成档位。F2 已经是「火力 1~5 档」，两个热学场景的加热控件保持一致。
- 这条不是体验优化：**1× 下验收第 12 条「改质量两段同步变」根本测不出来**，因为等不到平台结束。

**F3 比热容的口径：Q 是参数，ΔT 是结果**

同一设定热量 Q 下，三根升温条的高度分别表示水 / 煤油 / 砂石的 `ΔT = Q/(c·m)`，水最低——这正是「比热容最大」的视觉证据。**不要把 ΔT 做成滑杆**：一旦 ΔT 是用户设定值，三根条就必然等高、画面什么也没表达，而且与教材「相同热源加热相同时间、比较温度变化」的实验口径不符。砂石比热容取教材表原值 **0.92×10³**（不是教辅简写的 0.9）。默认 `Q=15 kJ`、`m=0.5 kg` → 水 7.1℃、煤油 14.3℃、砂石 32.6℃。主读数仍是 η，副读数显示水温升 ΔT。

**Q 的量程必须按「最烫的那个物质」封顶**：`heatQ` 实际上限 = `c砂石 × m × 90 = 82.8·m kJ`（m=0.5 → 41.4 kJ）。只按水封顶是不够的——砂石比热容最小，同热量下升温是水的 4.5 倍，若只保证水不超 90℃，砂石会冲到 400℃ 以上，学生一拉满就看到「水升温 238℃」这种荒谬值。用既有 `maxFollow`（跟随 `mass`）实现，不新增机制；联动系数在 JSON 里**显式声明 `"maxFactor": 82.8`**（`maxRule` 只写人类可读说明，禁止从它解析数字，见附录 B 联动规则）。默认值 15 kJ 在各质量档下都合法。

**F3 气缸的朝向不作为验收项**：进气门在屏幕左侧还是右侧，是绘图惯例而不是物理事实，不同版本、不同出版社的图本身就不统一，**不要按「课本是进左排右」去卡**。不可错的是三条硬对应：① 连**进气管**的那颗门才是进气门，只在吸气（φ720 的 0–180°）开；② 连**排气管**的那颗门才是排气门，只在排气（540–720°）开；③ 火花塞始终在两门正中，点火在 φ720≈360°。判据永远是「门 ↔ 管子 ↔ 冲程」的配对关系。为了让开合肉眼可读，**把「进气 / 排气」字样标在进、排气管的管口上**（不要标在气门盘上，会被缸盖缝隙遮住），开启的那颗门再配一个穿过管口进缸 / 出缸的流向箭头。

**F3 的 η：已定稿方案 A，且用动态钳制而不是报错兜底**

`η=W有/Q总` 需要 W有 和 Q总 两个量，现有参数（c、m、ΔT、rpm、冲程）都给不出来，不补就只能造数或写死，这都违反底线。定稿做法：

- 补两个滑杆 `Q总 0~500 kJ`、`W有 0~200 kJ`，`η = W有/Q总` 实时算，读数区显示百分比。
- **`W有` 的滑杆上限动态钳制到 `Q总`**（实际上限 = `min(200, Q总)`），拖动 `Q总` 变小时 `W有` 跟着被收紧。这样「η>100%」在物理上根本调不出来，不需要弹提示，也不需要事后校验。这和 A1 静止态是同一条原则：**不让用户调出无效状态，而不是调错后再报错**。
- `Q总 = 0` 时除零，读数区显示状态词「—」，不显示 `Infinity` 或 `NaN`。
- `Q总` 与 `W有` 的默认值取 100 kJ / 30 kJ，初始效率 30%，落在热机真实区间内，学生一眼能对上「70% 变成废气」。

**2. 场景列表**：项高 44px、`--radius-lg`、内边距 10×12px。结构：左起 4px 识别色竖条（仅选中显示）→ 图标 20px → 名称 13px/500 → 副行教材章节 12px secondary（如「人教版八下 · 11.2」）。选中态底 = 识别色 12% 透明 + 名称变 primary；hover `--color-surface-hover` 120ms。

**3. 参数滑杆（核心控件）**，每参数一区块、区块间距 12px，三行：
- 行 1：参数名 13px/500 左对齐；右侧数值读数 mono 13px/600 + 单位 12px secondary chip（`--radius-sm`，底 surface）
- 行 2：轨道高 4px、`--radius-full`、未填充底 `--color-surface-hover`；已填充段用当前模块识别色；拇指 16px 正圆 + 白描边 2px；hover/拖拽放大 1.25 倍 + `--shadow-glow`
- 行 3：min / max 数值 12px secondary 分列两端
- 行为：拖拽时数值实时刷新；3D 更新走 rAF 每帧合并（不逐事件渲染）；松手不回弹
- 键盘：Tab 聚焦后 ←/→ 单步、Shift+方向 ×10、Home/End 到端点
- **离散档位不做滑杆**：JSON 里 `type:"enum"` 的参数（表面材料、介质组合、接线柱接法这类教材本身分档的量），2~4 档用**分段按钮**（选中态与模块 Tab 同款视觉语言：识别色 15% 透明底 + 同色文字 + 内描边），5~6 档用**自定义下拉**（原生 `select` 样式不可控）；`options` 直接取 JSON 的 `label`。
- **滑杆联动约束**：参数之间存在依赖时（如 F3 的 `W有` 不得大于 `Q总`），被约束滑杆的 `max` 实时跟随 `min(声明上限, 依赖参数当前值)`，**超限时静默夹紧而不是弹提示**。需要系数时（如 `Q ≤ 82.8·m`）必须在 JSON 里**显式声明 `maxFactor`**，由 UI 计算 `min(声明上限, maxFactor × 依赖参数值)`；`maxRule` 只作人类可读说明，**禁止从它的中文描述里正则解析数字**——改一句措辞就会静默失效。这是通用规则，后续任何实验有联动都照此实现。

**4. 数值显示**：全部物理量读数统一 mono、右对齐；单位 12px secondary。数值变化瞬间 120ms 从 primary 色渐回正常色，提示「刚变了」。JSON 的 `result` 字段（由公式算出的结果量）渲染在滑杆区顶部的**独立卡片**里；公式存在分段条件时该位显示状态词（如「静止」）替代数值。**分母为 0 或无定义时显示「—」**，禁止出现 `NaN`、`Infinity`、`0%` 这类无效读数。
**次级读数**：`secondaryResult` 是可选字段，只有 F3（比热容 + 四冲程双段场景）用到。渲染规则——同款卡片、放在主卡下方 8px、数值降为 13px/500，**主次靠顺序表达，不加标签**；没有该字段的场景不渲染、不留空卡。它是通用卡片渲染器的一次普通调用，不是特例通道。

**5. 按钮**：重置（次级）底 `--color-surface` + 1px `--color-border`、文字 14px/500，点击后所有参数 300ms 补间回教材默认值并同步驱动 3D，toast「已恢复教材默认参数」；全屏（主）底 `--color-primary` 白字、高 36px、`--radius-md`，对整个应用容器调 `requestFullscreen`（面板保留），退出后文案变「退出全屏」。通用态：hover 提亮 120ms、按压 scale 0.97、disabled 40% 透明、焦点 outline 2px primary + `--shadow-glow`。

**6. 播放工具条**：视区左下悬浮胶囊，底 `rgba(16,24,40,.85)` + `backdrop-filter: blur(8px)` + `--radius-full` + `--shadow-2`。内容：播放/暂停按钮 + 速度分段控件。**全实验只做一套，档位统一为 0.5× / 1× / 2× / 4× / 8×**，由实验的 `speedOptions` 声明、`defaultSpeed` 决定预选项（热学 F1/F2 预选 8×）。行为约束见正文第六节「播放控制」。

**7. 视区叠加层**：左上当前实验 chip（图标 + 名称，半透明底 + blur，12px）；右下首次提示「拖拽旋转 · 滚轮缩放 · 右键平移」，显示 5s 后淡出且不再出现。

**8. 反馈**：Toast 右下角、2s 自动消失；场景切换超过 150ms 显示 24px spinner（primary）居中。

## B.8 与 3D 层的对接口径

- Token 直接落成 `:root` CSS 变量，并同时导出**一份 TS 常量表**给 three.js 用（场景背景、雾色、五科识别色），保证视区与面板视觉同源。
- UI 层只发「场景 ID + 参数对象 + 播放状态」，3D 层只读渲染、**不回写 UI 状态**；具体通道（事件总线 / store）以附录 C 架构为准。

## C.3 状态管理（自研发布-订阅，不引 Redux/Zustand）

```ts
interface PlaybackState { playing: boolean; speed: number; }

interface AppState {
  module: ModuleId;
  experimentId: string | null;
  params: Record<string, number | string>;    // 用户滑杆值 + 枚举档位
  playback: PlaybackState;
  readouts: Record<string, number | string>;  // 实验写入，UI 订阅显示
}
```

- 单向数据流：UI 操作 → `store.setState` → 订阅者各自响应，禁止反向直改 UI。
- 选择器订阅：组件只订阅自己关心的切片（如 `readouts.t`），避免全量刷新。
- 读数显示 100ms 节流合并写 DOM，防止每帧 `textContent` 抖动。

## C.4 UI ↔ three.js 通信（全部走 store，不散布事件总线）

```
用户拖滑杆 → paramSliders 写 store.params / 工具条写 store.playback
                ↓ store 订阅
engine ── params 变化 ──→ ctx.onParam(key, value) → 模型实时更新
engine ── experimentId 变化 ──→ sceneManager.switchTo(id)（懒加载 + dispose 旧的）
engine ── playback 变化 ──→ 仿真时钟启停 / 步长乘 speed（帧循环不停）
experiment ── emitReadout ──→ engine 写 store.readouts ──→ readouts.ts 显示
```

- 引擎对 UI 只暴露五个方法：`mount / setExperiment / setParams / setPlayback / reset`，全部由 store 订阅驱动，**引擎不回写任何控制状态**。
- readouts 是**单向显示数据**，只能被 UI 读取展示，绝不参与控制流，杜绝 UI↔3D 循环依赖。`emitReadout` 的键即读数卡标题字段，UI 按 JSON 的 `result` / `secondaryResult` 取数渲染，键缺失时显示「—」。
- **数据源约定**：`docs/附录A-实验清单.json` 即运行时 `experiments.json`，UI 元数据（模块分组、场景名、章节、参数、读数卡）全部由它自动渲染，**实验代码里不写任何 UI**。
- **高频例外**：OrbitControls 直接绑在 `renderer.domElement` 上消费 pointer/触摸事件，不经过 store（每帧 60 次的事件不进全局状态）。
- 重置：UI 侧做 300ms 补间、逐帧写 `store.params`；引擎 `reset()` 负责清仿真内部状态。两边分工，UI 不感知引擎内部。
- 切换实验时 `playing` 重置 `true`、`speed` 保留上次选择；色彩 token 由 `styles/tokens.css` 单一来源下发，3D 侧只读不另定。

## C.5 场景切换与防竞态

1. **切换令牌**（自增 id）防竞态：快速连点场景列表，旧切换未完成则作废其结果。
2. 时序：淡入 150ms → `import()` 拉 chunk → `build(ctx)` → 相机归位 → 淡出 150ms → 延迟 300ms 释放旧场景。
3. 旧实验释放：暂停 step → `reset()` 不调 → `dispose()`（实验清自己的内部引用）→ `disposeObject3D(root)` 遍历释放几何体/材质/每个贴图槽位 → `renderer.renderLists.dispose()`。
4. 资源池共享资源走引用计数，不在此销毁。
